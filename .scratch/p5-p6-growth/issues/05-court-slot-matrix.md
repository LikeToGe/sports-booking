# 05: 按时间和场地比较具体场次

**Status:** ready-for-agent

**GitHub Issue:** https://github.com/LikeToGe/sports-booking/issues/6

## Parent

https://github.com/LikeToGe/sports-booking/issues/1

## What to build

用户在场馆详情切换现有列表和时间 × 场地比较视图，理解可订与不可订状态，查看现价和取消截止后选择一个完整具体场次。

阶段：P5。用户故事：17, 18, 19, 20, 21, 22；验收：A5, A7, A16, A18。

所有功能任务包含所需的数据迁移、业务/API、页面和验证；追加迁移、不重写历史。测试优先现有 HTTP 与业务边界，关键交互在小程序/后台验收。

## Acceptance criteria

- [ ] 两种视图使用同一场次事实，展示开放、暂时占位、已预约、不开放等公开状态，并以文字辅助颜色。
- [ ] 保留真实起止时间，只能选择一个完整具体场次；长短场次不被拆成可自由拼接购买的小时格。
- [ ] 不展示占用者身份、联系人、预约标识、资金、员工备注或核销凭证，只展示公开不可订原因。
- [ ] 前置展示当前价格、取消截止和入场须知；实际预约仍重新校验库存和价格。
- [ ] 保留已有列表入口；在手机和多场地场景完成可读性、滚动、点击、加载重试和无障碍验证。
- [ ] 覆盖各种状态、不同长度、最后一个具体场次竞争及旧接口兼容，验证原预约资金与快照不变。
