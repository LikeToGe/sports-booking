# 10: 取消、超时和重新开放后发送空位提醒

## Parent

https://github.com/LikeToGe/sports-booking/issues/1

## What to build

在已有提醒登记与落地流程上增加空位提醒；具体场次因取消、支付失败/超时或人工重新开放而变得可订时，用户获得重新查询预约的机会。

阶段：P6。用户故事：33, 34, 36, 37, 38, 39, 40, 59, 60, 64；验收：A9, A10, A15, A16。

所有功能任务包含所需的数据迁移、业务/API、页面和验证；追加迁移、不重写历史。测试优先现有 HTTP 与业务边界，关键交互在小程序/后台验收。

## Acceptance criteria

- [ ] 覆盖各真实释放来源，必须满足当前可售及订阅时间条件；回滚、不满足截止或只是持续开放均不产生新事件。
- [ ] 一次从不可订到可订的事件最多提醒一次；再次占用后再次释放可形成新的稳定事件，不能周期扫描重复发送。
- [ ] 沿用登记撤回、过期、注销、消息/投递去重与重试规则，不对外保留名额或自动创建预约。
- [ ] 用户打开已被抢订的空位时看到当前不可订与主动可选替代；原资金业务号、锁、取消退款语义不变。
- [ ] 验证取消/支付超时/失败/重新开放、再次占用释放、事务回滚、撤回与重启，运行态完成消息到重新预约及原构成退款。
