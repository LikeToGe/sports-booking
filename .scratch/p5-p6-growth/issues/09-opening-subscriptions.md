# 09: 登记开售提醒并收到可查询的站内消息

**Status:** ready-for-agent

**GitHub Issue:** https://github.com/LikeToGe/sports-booking/issues/10

## Parent

https://github.com/LikeToGe/sports-booking/issues/1

## What to build

用户对指定场馆、运动、日期和时间范围登记开售提醒，在目标时段进入可售规则时收到一次消息，并可查看、撤回登记或从消息重新查询。

阶段：P6。用户故事：33, 34, 35, 37, 38, 39, 40, 59, 60, 64；验收：A8, A10, A15, A17, A18。

所有功能任务包含所需的数据迁移、业务/API、页面和验证；追加迁移、不重写历史。测试优先现有 HTTP 与业务边界，关键交互在小程序/后台验收。

## Acceptance criteria

- [ ] 用户只能登记本人需求，日期限当前预约窗口及下一次开放的一个日期，时间匹配与 P5 一致，不支持全城无限条件订阅。
- [ ] 重复有效条件幂等，登记可查看撤回；首次登记已有可订场次时引导查看，不伪造新开放事件。
- [ ] 批量调度根据已提交的可售状态产生消息，登记与开放事件稳定标识配数据库唯一约束去重，重复调度不重复提醒。
- [ ] 生成前复核有效登记和可售规则；所有目标时段不可再预约后到期，撤回/注销后不新投递，历史消息保持当前状态校验。
- [ ] 从消息保留原条件重新查询，明确未保留名额，已被订走时显示状态与可选替代；不创建支付占位或自动扣款。
- [ ] 复用现有站内/Mock 能力，失败同标识重试、成功去重，外部调用不影响预约资金；保留提醒入口与后续成功预约关联。
- [ ] 完成 A8/A10/A15、旧数据迁移、越权登记及小程序登记到消息到预约的完整验收。
