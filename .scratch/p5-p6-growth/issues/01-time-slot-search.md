# 01: 按可用时段和价格查找具体场次

**Status:** ready-for-agent

**GitHub Issue:** https://github.com/LikeToGe/sports-booking/issues/2

## Parent

https://github.com/LikeToGe/sports-booking/issues/1

## What to build

用户选择运动、日期、可用起止时间和单场次价格后，跨场馆查看实际可订具体场次；进入详情保留条件，并通过原预约流程完成预约。

阶段：P5。用户故事：1, 2, 3, 4, 5, 6, 7, 8, 61, 62, 64；验收：A1, A2, A7, A16, A17, A18。

所有功能任务包含所需的数据迁移、业务/API、页面和验证；追加迁移、不重写历史。测试优先现有 HTTP 与业务边界，关键交互在小程序/后台验收。

## Acceptance criteria

- [ ] 具体场次完整落在所选范围内，遵守场馆上架、场地启用、开放窗口与最晚预约规则；时间按 Asia/Shanghai 解释，拒绝逆序、相同起止和跨日条件。
- [ ] 价格按具体场次总价整数分过滤，场馆起价只取匹配结果；结果展示场馆、场地、运动、起止时间和现价，稳定排序并分页或有界返回。
- [ ] 原调用不传新参数仍可用；进入详情保留筛选，无结果时允许用户主动放宽，不静默更改日期或时段。
- [ ] 创建预约重新校验当前价格和库存，仍只对应一个具体场次；不将时间范围暗示为连续两小时预约。
- [ ] 保留最少的时段搜索入口与成功预约关联以观察转化，不进入计价、不新增通用埋点平台。
- [ ] 以隔离 HTTP 数据验证匹配、截止、价格变化与最后一个场次竞争；回归原资金冻结、取消和退款，完成小程序行为与交互验收。
