# 11: 按星期和小时查看预约利用率热力图

**Status:** ready-for-agent

**GitHub Issue:** https://github.com/LikeToGe/sports-booking/issues/12

## Parent

https://github.com/LikeToGe/sports-booking/issues/1

## What to build

场馆和平台授权人员在现有报表中筛选日期、场地和运动，查看星期 × 小时的可售分钟、已预订分钟及预约利用率，理解真正空闲与不可售的区别。

阶段：P6。用户故事：41, 42, 43, 45, 46, 47；验收：A11, A17, A18。

所有功能任务包含所需的数据迁移、业务/API、页面和验证；追加迁移、不重写历史。测试优先现有 HTTP 与业务边界，关键交互在小程序/后台验收。

## Acceptance criteria

- [ ] 按 Asia/Shanghai 自然日和小时将长短/跨小时场次拆为重叠分钟，以预订分钟/可售分钟计算，不按笔数替代时长，范围不超过 90 天。
- [ ] 支付占位只影响可售时间基底、不计确认分子，关闭/停用/不可供给时段排除；共用多运动场地按时间区间去重容量。
- [ ] 已确认占用按预约快照处理人工改时，与可售区间去重，分子不超过分母且不修改历史预约。
- [ ] 无可售分钟显示不可售、有容量但未预订显示 0%；历史以留存供给和快照为准，缺失来源显示数据不足，不填造历史。
- [ ] 显示计算口径、范围与生成时间，历史与未来分开；线上经营、线下登记、余额消费和真实收款口径不混合，不新增数仓。
- [ ] 报表权限复用现有规则，平台仅场馆级汇总，不因查看热力图获得顾客或导出权限。
- [ ] 使用可手工核对的数据验证分钟与所有边界，完成隔离 HTTP、权限及后台热力图可读性/空失败反馈验收。
