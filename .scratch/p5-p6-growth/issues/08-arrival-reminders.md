# 08: 到场提醒直达本人预约并支持可靠 Mock 投递

**Status:** ready-for-agent

**GitHub Issue:** https://github.com/LikeToGe/sports-booking/issues/9

## Parent

https://github.com/LikeToGe/sports-booking/issues/1

## What to build

已确认线上预约开始前两小时产生一次到场提醒，临近确认及时补发；用户从消息打开本人预约、导航和核销凭证，运营能追踪 Mock 投递失败与重试。

阶段：P6。用户故事：55, 56, 57, 58, 59, 60；验收：A14, A15, A16, A18。

所有功能任务包含所需的数据迁移、业务/API、页面和验证；追加迁移、不重写历史。测试优先现有 HTTP 与业务边界，关键交互在小程序/后台验收。

## Acceptance criteria

- [ ] 采用开始前两小时固定触发点，临近确认补发一次，已开始或非已确认状态不补发，不新增通用配置中心。
- [ ] 调度与即时补发使用预约业务标识去重；并发、重复调度与服务重启不重复生成消息。
- [ ] 生成与投递前校验当前状态；取消、完成、未到场、失效和用户注销后不发起新投递；线下无可信用户时不按手机号猜身份。
- [ ] 消息不公开核销码或敏感联系人，详情按本人权限显示当前状态，复用原导航/须知/核销凭证。
- [ ] 分别记录站内消息与投递尝试/结果，Mock 不宣称微信送达，暂时失败使用同一标识重试，成功不重复投递。
- [ ] 投递不持有预约/余额锁，不影响取消或退款事务；覆盖 PRD A14/A15、隔离 HTTP 完整落地和消息中心界面验收。
