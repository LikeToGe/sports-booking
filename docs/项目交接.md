## 项目目标与边界

“约场”是郑州市多场馆固定场次预约的本地 Mock MVP。用户使用微信原生小程序找场馆、创建预约、模拟支付并出示核销凭证；平台和场馆使用 Vue 后台运营。

当前范围只覆盖本地完整演示。真实微信登录、支付、退款、订阅消息、定位推荐、多城市、佣金结算、会员优惠、评价、售后工单、复杂权限、组合场地、自由时长、课程和赛事均不在 MVP 范围内。

## 已实现的业务闭环

### 身份与权限

- 平台管理员、场馆管理员与小程序用户均可建立 Redis 会话；小程序使用 Mock code 登录。
- 后端从后台或小程序会话推导平台、场馆、用户和员工身份，Controller 不信任客户端传入的归属 ID。
- 用户可绑定一个场馆员工身份；该身份不影响其普通预约能力。

### 场馆供给与运营

- 平台可创建、上架或停用场馆，并维护平台运动类型。
- 场馆可维护资料、封面、场馆运动类型、场地与员工；一个场地可关联多个运动类型，但同一时段只接受一笔预约。
- 场馆可维护周场次、复制星期模板、生成或临时增加具体场次、关闭整天或单个场次，并重新开启符合条件的已关闭场次。
- 场馆可创建电话/到店的线下预约，或带原因取消预约；平台和场馆均有经营报表入口。

### 用户预约与履约

- 小程序可按平台运动类型、日期和名称查找场馆，查看场馆、场地和具体场次。
- 用户可填写或复用联系人资料，创建线上待支付预约；创建流程锁定具体场次并建立 10 分钟支付占位。
- 模拟支付确认预约；用户在取消截止前可取消，场馆取消与用户取消均走模拟全额退款和通知记录。
- 预约详情提供动态二维码与 6 位短码。员工可扫码或输入短码核销，并查看本人核销记录。
- 定时任务每分钟释放超时待支付预约，并将结束后仍未核销的已确认预约标记为未到场；每日按业务时区生成预约窗口内的具体场次。

### 状态与一致性

- 预约：`PENDING_PAYMENT -> CONFIRMED -> COMPLETED`，也可进入 `CANCELLED` 或 `NO_SHOW`。
- 具体场次：`OPEN -> HELD -> BOOKED`，也可进入 `CLOSED`；取消或支付超时会按可预约条件释放。
- `s_session_slot` 以 `(court_id, start_at, end_at)` 唯一约束防止同场地重叠；线上创建预约在事务中以行锁占用场次。
- 预约保留场馆、场地、运动、时间和价格快照，不随资料或周场次修改而变化。

### 平台服务费验证

- 平台管理员可为每个场馆配置 `0%～30%`、最多两位小数的服务费率；场馆管理员只读。
- 新线上预约保存服务费率快照，历史和线下预约按 `0%`；调价不追溯已有预约。
- 月度结算只统计已完成或未到场且费率快照大于 `0` 的线上预约，按场次结束月份归集。
- 服务费不舍入或截断，后端以整数微元精确汇总并返回最多六位小数的元金额。
- 平台和场馆复用现有报表页查看汇总与逐笔明细；当前不建账本、月账单状态机或真实资金链路。

## 已实现的界面

- 管理后台：登录；平台场馆、平台运动类型、平台报表；场馆今日场次、预约、场地、排期、具体场次、员工、资料、场馆报表。
- 小程序：找场馆、场馆详情、确认预约、模拟支付、我的预约、预约详情、个人资料、员工绑定、扫码/短码核销、核销记录，共 10 个页面。

管理后台并非 Mock 页面：各页面通过 `admin-web/src/api.ts` 请求后端；小程序页面通过 `miniapp/utils/api.js` 请求后端。

1. 场馆级服务费率、预约费率快照和只读月度结算已经实现并通过自动化与本机运行态验证。
