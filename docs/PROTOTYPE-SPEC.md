## 1. 评审方法

本文件用于检查低保真原型是否覆盖 MVP 功能闭环，不作为最终视觉稿。

每个页面必须能够回答五个问题：

1. 谁能进入，数据范围是什么。
2. 用户为了完成任务需要看到哪些字段。
3. 当前允许哪些操作，危险操作如何确认。
4. 正常、空、禁用、失败和处理中状态如何恢复。
5. 操作成功后进入哪个页面或业务状态。

覆盖标记：

- `主页面`：出现在角色主导航中。
- `子页面`：从列表、卡片或主操作进入。
- `弹窗`：用于短表单、确认或高风险操作。
- `状态页`：表达处理中、失败、完成等业务结果。

### 1.1 跨端共享 Mock 订单

原型以 `BK202608040019` 作为当前演示订单。用户、场馆管理员、平台管理员和核销店员读取同一份 Mock 事实，不允许各端使用不同订单号或互不影响的独立状态。

```text
用户选固定时段
  -> PENDING_PAYMENT / PAYMENT_LOCKED
  -> 模拟成功：CONFIRMED / BOOKED
  -> 店员核销：VERIFIED，凭证失效并写入两类核销记录
  -> Mock 系统任务：COMPLETED
  -> Mock 计费任务：生成一次 6% 服务费明细
```

异常路径同样共享状态：

- `UNKNOWN` 支付使库存保持 `UNKNOWN`，只能查询或等待安全关单，不能直接重新售卖。
- 用户取消使订单进入 `CANCELLED`、库存恢复 `AVAILABLE`、退款进入 `REFUND_PROCESSING`，到账后才显示退款成功。
- 场馆取消将库存置为 `INTERNAL_BLOCKED`；退款到账不自动解除该库存原因。
- 已核销、已取消、待支付或已完成订单的二维码/短码均拒绝核销，并保留明确失败原因。

该共享状态只用于原型评审，不替代服务端订单行锁、幂等键、持久化 outbox 或真实支付 Provider。

## 6. 跨页面状态与反馈

| 类型 | 规则 |
| --- | --- |
| 成功反馈 | 保存、新增、暂停、取消、核销和收款均显示明确结果 |
| 处理中 | 支付、退款和任务状态不得用“失败”替代未知；提供查询或返回入口 |
| 危险操作 | 暂停、场馆取消、用户取消、店员停用和标记账单已支付必须二次确认 |
| 空状态 | 说明当前没有什么，并提供唯一合理的下一步操作 |
| 权限拒绝 | 说明无权访问的范围，不泄露对象是否存在及敏感字段 |
| 手机号 | 默认脱敏；完整号码查看前填写原因，成功后显示并记录审计 |
| 返回行为 | 子页面返回来源列表并保留筛选；状态页返回对应业务首页 |
| 深链接 | Hash 包含角色和页面 ID，刷新后恢复当前页面 |

## 7. 本轮原型完成标准

- [ ] 上述所有主页面均可从角色导航进入。
- [ ] 所有子页面至少有一个可发现的入口和明确返回操作。
- [ ] 高风险操作使用弹窗并展示业务影响。
- [ ] 支付未知、退款处理中、短码失败和门禁暂停有可恢复状态。
- [ ] 平台与场馆完整手机号查看均生成可见审计反馈。
- [ ] 375×812、812×375、1024×768、1440×900 无页面级横向溢出。
