## #2 代码与契约

- 新增 `GET /mini/slots/search`，必填日期，可选运动、名称、同日递增起止时间与单场总价整数分；完整包含具体场次，每页 20 条，按开始时间/场馆/场地/场次 ID 稳定排序。`page` 为 1–10000，空结果返回空数组；页满可继续请求下一页，不返回虚构总数。
- 仅查询上架场馆、启用且仍关联该运动的场地/运动、OPEN 场次、预约窗口内且严格晚于最晚预约截止的供给。全部日期按 Asia/Shanghai 解释。筛选范围不是连续预约时长。
- 新检索直接展示每个匹配具体场次的现价，不展示全天起价。未选时段或价格时原场馆首页保持旧行为。详情增加同样的可选筛选，旧 HTTP 请求仍可用。
- 首页保留日期、运动和筛选进入详情；编辑条件显示待检索，失败不静默清除或放宽。首页与详情防止旧请求覆盖新条件，错误不与空结果混淆。
- `BookingCreateRequest` 新增可选 `expectedPriceFen` 和 `entryType`。所有端侧预约提交看到的整数分价格，变价返回 `SLOT_PRICE_CHANGED`，要求返回刷新重新确认；旧请求可省略价格字段，仍按当前价格创建。
- 创建服务在原场次锁/事务内重新校验场馆、场地、运动关联、窗口、截止、库存和现价，再执行既有资金冻结与支付。没有新增收费规则或支付状态机。
- V11 为预约追加可空 `entry_type`。`TIME_SEARCH` 随预约同事务写入，通过现有预约状态关联确认/取消结果；来源由客户端声明，只用于入口统计，不参与权限与计价，不宣称完整搜索漏斗或真实到场。
- `docs/openapi.yaml` 来自隔离运行态 Springdoc，服务器地址恢复为仓库默认 8089；新增路径与 Request/VO schema 已校对。
