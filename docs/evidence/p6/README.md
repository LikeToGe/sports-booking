## 已实现链路

- 到场提醒：本人已确认线上预约开始前两小时生成；临近确认在原事务提交后补发，使用相同预约业务键。本人详情保留预约快照并提供当前场馆导航与入场须知，停用馆也不会使本人历史详情不可读。
- 开售与空位：允许登记当前窗口及下一开放日；登记唯一幂等、可撤回、按本人查询。首次已有 OPEN 仅引导查看。列表显示窗口与截止规则，日期选择限制到可登记上限。
- 释放事件：原业务事务仅写稳定事件；支付失败按预约业务号去重，人工重开及真实状态释放使用本次操作标识。独立任务按已提交事件的精确 ID 集合批量生成消息，避免并发事件被误标处理。事务回滚不留事件/消息。
- 投递：站内消息与每次 Mock 尝试分别保存；投递前复核预约/登记/供给/账号，失效历史消息保留但不发新投递。失败沿同 ID 重试；已有 SUCCESS 的重启遗留只补状态，不重新调用 Adapter。Mock 不声称微信送达。
- 利用率：批量读取留存供给与预约快照，按场地并集合并时间区间，再分业务自然小时；预约和取消笔数独立按 ID 去重。历史与今日/未来分开，明确数据不足、不可售与 0%。平台接口不返回场地及低利用明细；场馆下钻保留运动、场地及区间重叠，支持次日零点。
- 顾客经营：有效预约次数和常约小时只在本馆计算；线上完成/核销、最近有效预约及来源明确。30 天分组按线上 completed_at 且没有未来确认预约，标签不放大次数。标签/回访复用固定 CUSTOMER_OPERATIONS_EDIT，管理员与员工身份分列留痕，关系删除有审计。
- 回访：只为当前符合分组的本馆顾客创建；唯一约束只限制未完成目的，条件更新避免并发覆盖。可对照处理时间与其后日期的有效预约场次及来源，按场次开始快照统计；不推断创建时刻或营销因果。
- 追加 V18–V23；未重写已提交 V1–V11。V12–V15 属于本次 P5 增量。V16–V17 未使用，版本间隙不代表迁移缺失。
